## Existing boundary

`LeanLaunchConfig` validates absolute ledger path, exact account/deployment and instrument/rule coverage; `prepare_project` writes `main.py`, `config.json`, `qal-execution.json` and a hash-bound manifest with `runtime_verified=false`. `verify_project` checks config, deployment and implementation hashes. `check-runtime` only imports `QCAlgorithm` and `System.Decimal` and explicitly does not verify runtime.

`AIQuantStackAlgorithm.Initialize` requires `qal-config`, verifies the project and **rejects non-live engine mode**, then subscribes second-resolution equity/crypto, constructs `LeanAlgorithmPort` and typed execution, restores paper state for paper accounts, and attaches native readers only for live accounts. `OnData` calls bridge `step`, `OnOrderEvent` forwards events, and shutdown closes ledger/readers. `LeanVenue` owns capture, rules, submit, lookup, cancellation and receipt validation/recovery; `LeanAlgorithmPort` projects runtime identity, balances, orders and events. These are the existing execution path, not a second executor.

## Proposed acceptance experiment

1. Coordinator choose source-build versus traceable image digest, platform and resource budget; verify candidate APIs and dependencies inside that exact image. Mount a read-only approved repository at a stable absolute path, plus isolated writable temporary project, ledger and synthetic data directories. Install project dependencies only inside a reproducible derived image, pin and record them; no host installation. Assert `src.execution` imports resolve to the mounted checkout and `AlgorithmImports`, `QuantConnect` and `System` resolve inside the engine environment.
2. Prepare a paper `LeanLaunchConfig` with `PaperBrokerage`, one supported instrument, exact rules, isolated ledger and matching absolute container paths; seed a single valid canonical intent through existing admission interfaces. Supply finite, deterministic locally generated price data through an explicitly configured local feed. Disable outbound networking and credentials, and enforce a short wall-clock timeout and cleanup. Record exact image, config, data hashes and commands.
3. Start the actual engine in live engine mode with paper brokerage and the local feed; do not set live-capital authorization. Observe real initialization, `OnData`, a single actual engine ticket and `OnOrderEvent`, then verify ticket identity, event and ledger reconciliation from retained artifacts. Require clean termination and no provider access. A missing event, incompatible feed, dependency or failed identity check is a failure, not acceptance.

This is currently a **design**, not a runnable recipe: the existing live-mode guard means a normal historical backtest cannot exercise this algorithm. Whether upstream supports a finite synthetic local feed with live-mode PaperBrokerage, paper restoration, and a deterministic shutdown without a provider is unresolved. Coordinator must decide whether to authorize a narrowly scoped test harness/feed or a reviewed test-only mode if it does not; neither may bypass the production guard silently. Confirm PaperBrokerage local-job identity/configuration and synthetic feed format against the pinned engine before implementation. Do not fabricate events or weaken receipt validation. Passing this test would establish only the bounded paper engine path, not native brokerage, strategy profitability, RD acceptance or live trading readiness.
